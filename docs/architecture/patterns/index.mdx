:::tip Key takeaways
- A **saga** replaces a distributed transaction with a chain of local transactions and compensating actions.
- **Event-driven** designs trade temporal coupling for eventual consistency. Plan for duplicates, reordering and
  replays from the start.
- Both need a reliable way to publish events with a state change, i.e. the
  [transactional outbox](/docs/architecture/microservices/messaging-brokers).
:::

How these patterns fit into a service landscape (boundaries, data ownership, messaging) is covered in
[Microservices](/docs/architecture/microservices).
